# 项目结构与架构设计

状态：**提案**。跨平台、Linux 首包已确认；技术栈、本地优先方案、加密与 AI 部署待确认。此文档展示目标目录，不表示目录内已有实现。

## 1. 技术方案建议

推荐评估 Tauri 2 + React + TypeScript + Vite + SQLite。

- React/TypeScript：对话、编辑、历史与复盘界面，类型化桌面接口。
- Tauri/Rust：原生桥接、持久化、核心业务、文件与密钥访问；不开放任意系统操作。
- SQLite：记录与草稿的持久事实来源，版本化迁移；普通 SQLite 不等于加密数据库。
- Mock AI：先验证结构、失败路径和完整循环；远程或本地真实模型需后续授权。

优点是桌面体积与权限边界较易控制；代价是 Rust + TypeScript 双语言及 Linux WebKitGTK 等原生依赖。Electron 可减少语言切换，但包体与渲染安全配置成本更高。选择前评估本机环境与团队维护能力，不同时维护两套桌面壳。

## 3. 依赖边界

```text
UI → Desktop Client → Commands → Application → Domain
                                      ↓
                               Infrastructure
```

- 领域层不依赖 React、Tauri、文件、网络或数据库。
- 应用层通过明确接口访问存储、AI、时钟与文件能力；装配层注入实现。
- Rust 领域层建议作为聚合与周期规则的单一实现，前端只展示结果，不再用 TS 复制统计算法。
- Commands 校验参数并调用用例，不直接堆叠全部 SQL 与 Prompt。
- 禁止 UI 任意 SQL、任意文件路径、shell 执行或直接获取 API Key。
- 共享契约需可验证：生成类型或固定 DTO + 双端契约测试；具体方法在 Plan 01 决定。
- 长任务后台执行，经带任务 ID 的事件提供进度；UI 退订和关闭不造成静默重复任务。

## 4. 纵向数据流

### 记录

输入 → 本地草稿持久化 → 可选 AI 抽取 → 校验 → 用户编辑确认 → 事务保存记录 → 本地计算事实反馈。

保存是独立于 AI 的用例；AI 失败不丢原文。AI 回答返回时比较草稿版本，旧响应不能覆盖用户的新编辑。

### 复盘

区间与时区 → 字段聚合 → 来源快照 → 可选 AI 叙述 → 引用校验 → 复盘草稿 → 用户确认。

UI 的复盘生成不是一键「已完成」；草稿与确认结果区分。记录变化使相关输入失效，保留用户已编辑的复盘并显式标记过期。

### 删除与备份

确认操作范围 → 事务删除记录与关联数据 → 清理派生缓存/引用 → 标记受影响复盘 → 反馈结果。备份、外部导出副本有单独说明，不宣称全世界副本都被删除。

## 5. 桌面适配与安全

- 数据与日志使用系统应用目录，路径由平台 API 获取，不拼接 `/home/...` 或盘符。
- 密钥由系统凭据适配层访问；不作为普通 DTO 返回前端。
- 无默认遥测上传、无默认云同步、无无需授权的历史库外发。
- SQLite 本地备份采用一致性快照能力，不能只复制一个可能存在 WAL 的活动数据库文件。
- Markdown/富文本作不可信内容渲染，禁执行 HTML/脚本；外链与模型输出不触发系统命令。
- Linux 首包验证实际环境；Windows/macOS 先保持接口可移植，后续实机测试后再声明兼容。

## 6. 不提前引入

微服务、独立 HTTP 服务、通用插件系统、复杂事件总线、账号支付、向量数据库、移动端、云同步与跨设备冲突解决。

真正出现需求时提交 ADR 与新 plan。架构目标是把一次记录与一次周报做可靠，不是先搭一套平台。
