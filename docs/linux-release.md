# Linux 首包与发布设计

已确认：跨平台设计，Linux 优先打包。未确认：首测发行版、CPU 架构、包格式、最低系统版本。

## 1. 确认前不写死发行方式

候选格式需结合最终框架评估：

- AppImage：便于直接分发，但不等于无需任何系统依赖或兼容全部发行版。
- deb / rpm：安装与依赖表达更规范，但对应特定发行版族，不能当 Arch 原生包。
- Arch 包或其他方式：适合明确目标环境，增加维护范围，需单独确认。

用户当前在 Linux 不足以决定首包格式。构建依赖、签名与升级方案到 Plan 07 确认，不擅自安装系统软件或配置发布服务。

## 2. 发布前检查

- [ ] 记录发行版版本、架构、Wayland/X11、桌面环境、图形与 WebView 依赖。
- [ ] 依赖安装遵循实际系统与用户授权，项目依赖用项目工具。
- [ ] 使用冻结锁文件和明确工具链构建，记录版本与构建命令。
- [ ] 检查包内无密钥、真实日记、开发数据库、调试日志。
- [ ] 无需源码目录即可冷启动，数据写入系统应用目录。
- [ ] 中文输入法与 Enter 快捷键、高 DPI、窗口尺寸可用。
- [ ] 断网/关闭 AI/额度耗尽仍能记录、查看与导出。
- [ ] 安装、启动、退出重启、升级迁移、备份恢复均有证据。
- [ ] 更新失败不影响旧数据库；用户主动卸载是否保留数据有说明。
- [ ] 输出 SHA-256、版本、兼容范围、已知问题与数据目录说明。

## 3. 内测分发

GitHub 仓库默认私有。是否使用私有 Release、邀请内测协作者或另行分发安装包，发布前再确认；不创建公开下载链接、不开放仓库、不擅自邀请账号。

P0 不默认启用自动更新。若后续启用，需决策签名、下载校验、回滚与迁移兼容。

## 4. 验证矩阵

| 平台 | 当前规划 | 通过标准 |
| --- | --- | --- |
| 当前 Linux 本机 | 首次开发与烟测 | 实际桌面壳完整流程 |
| Linux 首发环境 | 待指定 | 安装包冷启动、升级与恢复测试 |
| 其他 Linux 发行版/架构 | 未承诺 | 单独构建或兼容性验证 |
| Windows | 后续 | 原生构建与实机验证后声明支持 |
| macOS | 后续 | 原生构建、系统权限及实机验证后声明支持 |

源码可跨平台、CI 构建成功、包能启动和产品完整可用是四个不同结论，发布说明必须区分。
