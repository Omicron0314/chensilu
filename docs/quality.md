# 测试策略与完成标准

当前没有测试代码和运行命令。以下是建立工程后的验收设计，不是已有通过记录。

## 测试分层

| 层级 | 核心范围 | 验证方式 |
| --- | --- | --- |
| 领域单元 | 周期、时区、时长聚合、确认状态、重复计时 | 固定时钟与合成记录，纯逻辑测试 |
| 存储集成 | 草稿、事务、迁移、幂等、删除与缓存失效 | 临时 SQLite 与故障注入 |
| AI 契约 | JSON/Schema、引用、过期响应、超时取消、有限重试、额度 | Mock 正常与异常响应 |
| UI 组件 | 编辑、跳过、确认、状态、错误恢复、来源导航 | 最终栈适配的 UI 测试 |
| 原生端到端 | 实际桌面启动、IPC、系统目录、持久化与文件操作 | Linux 真实桌面壳；浏览器测试不能替代 |
| 打包与升级 | 安装、冷启动、升级迁移、恢复 | 目标环境安装包手工或可重复脚本验证 |

## 合成测试数据

至少涵盖：

- 7 天内多个目标、无目标、未知时长、约数、明确 0 分钟。
- 正反馈未确认/已确认/跳过/今天没有、空状态与空反思。
- 一项行动关联多个目标、重复保存请求、修改日期、删除源记录。
- 跨午夜、跨月、夏令时与记录时区变化。
- AI 非法 JSON、幻觉来源、与事实不符、过期版本、长文本、取消后迟到响应。
- 中文输入法、特殊字符、含恶意 HTML 或指令的日记文本。

不要以「测试里没有数据」掩盖真实空状态；不要复制用户真实日记进 fixtures。

## 必验场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| T01 | 输入后应用异常退出并重启 | 恢复最近成功持久化草稿，说明未保存窗口 |
| T02 | 关闭 AI、断网或额度耗尽 | 不发起新 AI 请求，仍能保存、查看、导出 |
| T03 | 保存重试/响应迟到 | 不重复生成记录，不覆盖较新用户输入 |
| T04 | 周报统计与来源 | 与手算结果一致，未知项有说明，引用有效 |
| T05 | 编辑/删除源记录 | 派生内容失效或清理，确认版不静默被重写 |
| T06 | 迁移中断/失败 | 原数据可恢复，不留下伪成功状态 |
| T07 | 备份与恢复 | 一致性快照，恢复到独立测试目录后数据关系正确 |
| T08 | 导出和删除 | 导出格式可解析且无凭据，删除范围和副本说明清楚 |
| T09 | 恶意输入与错误日志 | 不执行指令/脚本，不泄露正文或密钥 |
| T10 | Linux 安装包 | 实际安装/启动，中文输入、高 DPI、持久化可用 |

## P0 完整流程

`打开桌面应用 → 回答 2–3 轮或自由写 → 编辑五栏草稿 → 保存 → 看事实反馈 → 选择周报区间 → AI 初稿 → 编辑确认 → 点回来源 → 导出 → 备份恢复`。

Mock 模式通过只能说明应用闭环可用；真实 AI 的质量、真实费用及免费循环是否成立需要获批提供商测试，不能混为一谈。

## 完成定义

- 对应需求编号和 plan 验收完成，任务复选框有证据。
- 实际执行仓库存在的格式、类型、lint、单元/集成测试与相关构建；命令和结果可回查。
- 原生能力在真实 Linux 壳验证，清楚标注 Wayland/X11、发行版与架构。
- 无已知丢数据、密钥泄露或阻断记录入口问题。
- 变更有必要文档；未完成或受阻部分写明，不报假通过。

每次 plan 完成记录至少包含：变更文件、实际命令、验证环境、测试结果、未覆盖项、风险、下一步。CI 暂时不能启动图形环境时必须保留手工验证门禁。
